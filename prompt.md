# Teatatu Events — Reusable AI Development Prompt

This file distils the design contract behind the Teatatu Events WordPress plugin into a prompt for an AI coding assistant, so future changes stay consistent with how the plugin was built. [`SPEC.md`](SPEC.md) is the full design; this file is the working summary.

## How to use this

1. Paste the **Prompt template** below into a fresh AI session.
2. Fill in `<describe the change>`.
3. Point the AI at the `teatatu-events/` folder — it must read the relevant `includes/*.php` files before changing them, not regenerate the plugin.

---

## Prompt template

```
You are extending an existing WordPress plugin, "Teatatu Events" (folder teatatu-events/, prefix teatatu_events_). Read the existing code before changing it — do not regenerate files from scratch.

CHANGE REQUESTED: <describe the change>

Preserve these invariants unless the change explicitly asks to alter them:

1. Standard WordPress tables only. Events are posts (teatatu_event); places, tags and areas are taxonomies; everything else is post/term meta or options. No custom tables.

2. Prefix teatatu_events_ for functions, hooks, meta (_teatatu_events_*), options, capabilities, CSS classes use tte-. The only exception: internal post types use teatatu_evt_ (teatatu_evt_series, _link, _rssfeed, _webfeed, _icalfeed, _ldfeed) because post_type is limited to 20 characters. Check the length of any new post type. Never reuse a teatatu_news_ identifier — the plugin must run side by side with Teatatu News.

3. Dates: _teatatu_events_start / _end are UTC Unix timestamps; display with wp_date() in the site time zone. Upcoming = end ≥ now; past = ended. All upcoming/past/range queries go through teatatu_events_query_args(). All-day events snap to whole local days.

4. One writer: every path (admin form, meta box, REST `event` field, importers, series, copies) validates through teatatu_events_validate_fields()/teatatu_events_save_fields(). Multi-step writes go through teatatu_events_batch_write() so teatatu_events_refresh_derived() runs once, after meta AND terms are in place. Derived values (default end, neighbourhood term, needs-venue clearing, fuzzy key, change propagation) live in refresh_derived — don't compute them anywhere else.

5. Places: Venue term = Location + structured address (term meta teatatu_events_addr_*). One formatter: teatatu_events_format_address(_parts)(). Address parsing/normalising lives in includes/address-core.php (pure PHP, shared with the build tool). Venue matching (name/alias → address → coordinates) is teatatu_events_match_venue(). Imports never create venues or tags.

6. Neighbourhoods: exactly three seeded terms with fixed internal keys (matipo, beach, harbourview); names are per site, and slugs are a network setting that a rename updates everywhere they are stored (old slugs stay as aliases). Resolution: venue/event override → street rules (network option, every rule listed and editable on the Neighbourhoods tab; rules may split a street by house number and odd/even side; loaded once on activation from assets/data/neighbourhood-streets.json, never read from a code table at runtime) → coordinates (assets/data/neighbourhoods.geojson boundary lines + peninsula outline) → none; unresolved peninsula addresses are flagged. The data is generated by tools/build-neighbourhood-streets.php from OpenStreetMap; it fails if a street's neighbourhoods interleave. No external geocoding calls at runtime.

7. Capabilities: the agent role (teatatu_events_agent) drafts and proposes changes via draft copies; it never gets publish_, edit_others_, edit_published_teatatu_events_items, manage_teatatu_events_feeds/series/links, or manage_ for venues/tags/neighbourhoods. teatatu_events_guard_curated_term_creation() blocks curated-term creation on every path. Adding a capability requires bumping TEATATU_EVENTS_VERSION (caps re-sync on admin_init when the version changes).

8. Images are link-only: store and serve the submitted URL; resolver order post → Source default → Venue default. No sideloading, no 'thumbnail' support.

9. Importers share one pipeline (includes/import-common.php): each importer only builds candidates (teatatu_events_{type}_build_candidates()). Draft-first; unreviewed drafts resync; published events get a pending update unless the feed auto-applies; auto-publish/auto-apply can only be written by users holding publish/edit-published caps (a lower-privileged save leaves them untouched). Removed at source: published upcoming events missing from a successful, COMPLETE fetch on N consecutive checks become Cancelled immediately and are flagged; never deleted. Preview uses the same build/place/filter code as a real import. Every importer writes _teatatu_events_external_key.

10. Shortcodes come in pairs: every display (list, grid, latest, calendar, archive, subscribe) has a site and a network version rendered by ONE function with scope 'site' | 'network'. Network data comes from teatatu_events_get_network_feed_items() (also used by the network REST and iCal feeds); its cache key includes only attributes that change which events are fetched. Network listings dedupe via teatatu_events_dedupe_items() and ignore linked events. Per-instance query params use a hash of the shortcode's attributes.

11. Caching uses version counters (teatatu_events_bump_cache_version()) — bump on any event, link or term change rather than tracking keys.

12. Multisite: per-site registration on init; network-wide behaviour only via the Master Site (aggregation) or the link registry (linked events). Provision only the sites a Network Activate covers. Inside switch_to_blog() never call flush_rewrite_rules() — use teatatu_events_reset_rewrite_rules(). Admin forms post to admin_url('admin-post.php') (there is no network admin-post.php).

13. Security baseline: nonces on every form/handler; narrowest current_user_can(); verify an ID is really ours (get_post_type()/taxonomy) before acting; never pass post_type to wp_update_post for an existing ID; escape all output, sanitise all input; DOM selectors are sanitised to a closed character set before XPath interpolation; third-party URLs are fetched with wp_safe_remote_get() and a size cap.

14. Update in lockstep: readme.txt, the in-admin Shortcodes tab (includes/admin-shortcodes.php), SKILL.md and MCP-GUIDE.md (anything agents touch over REST), SPEC.md, the Version header + TEATATU_EVENTS_VERSION, and the readme changelog.

Ask before changing: the agent capability boundary, the standard-tables rule, link-only images, the off-by-default auto-publish/auto-apply toggles and who may switch them on, or the removed-at-source safeguards.
```

## Architecture map

| File | Responsibility |
|---|---|
| `teatatu-events.php` | Header, constants, activation/deactivation, per-site provisioning, new-site hook, rewrite reset |
| `includes/capabilities.php` | Roles/caps, version-gated re-sync, curated-term guard |
| `includes/multisite.php` | Master Site, cache versions, site info |
| `includes/settings.php` | Settings page and option helpers (`teatatu_events_setting()`) |
| `includes/post-type.php` | All post types, event details block, external redirect, JSON-LD, draft-copy exclusion |
| `includes/taxonomies.php` | Five taxonomies and term meta |
| `includes/event-data.php` | Meta registration, validate/save, derived values, date formatting, query args, normalised item |
| `includes/address-core.php` | Pure-PHP address parsing, normalising, street rules, point classification (shared with the build tool) |
| `includes/address.php` | Venue address formatting/saving, venue matching |
| `includes/neighbourhoods.php` | Seeded terms, resolver, overrides, re-resolve job |
| `includes/meta-boxes.php` | Shared event fields renderer, native meta boxes |
| `includes/admin-columns.php` | Native list columns and sorting |
| `includes/copy-draft.php` | Duplicate, Edit as draft, merge/conflict, row actions |
| `includes/recurrence.php` | RRULE engine, series sync, series cron |
| `includes/dedupe.php` | URL normalising, external keys, network dedupe, key backfill |
| `includes/linked-events.php` | Links, snapshots, registry, propagation, shadowing, reconciliation |
| `includes/calendar-ics.php` | iCal rendering, raw text/calendar serving, add-to-calendar and subscribe links |
| `includes/shortcodes.php` | Twelve shortcodes, queries, network aggregation, renderers, filters, calendar |
| `includes/rest-api.php` | `event` field, query params, agent rules, teatatu-events/v1 routes |
| `includes/import-common.php` | Feed config, DOM helpers, date/status parsing, JSON-LD extraction, the import pipeline, pending updates, preview |
| `includes/{rss,html,ical,ld}-importer.php` | Candidate builders + cron ticks |
| `includes/feeds-admin.php` | The four feed tabs and handlers |
| `includes/cron.php` | Hook list, interval, schedule/unschedule |
| `includes/admin-*.php` | Maintenance screen tabs |
| `includes/updater.php` | GitHub Releases updater (`TeAtatu/Teatatu-events`) |
| `tools/build-neighbourhood-streets.php` | Regenerates the neighbourhood data from OpenStreetMap |
| `uninstall.php` | Retention-aware cleanup (Events data only) |
